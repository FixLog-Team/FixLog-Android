# 로그인 방식 전환 가이드 (WebView ↔ Custom Tabs)

> 이 문서 하나로 로그인 구현을 **두 방식 사이에서 왕복**할 수 있다.
> 각 방식이 무엇을·왜·어느 파일의 어느 부분을 바꾸는지 정리한다.
> 연계 문서: `OAUTH_CUSTOM_TABS_전환.md`(상세 설계), `서버_로그인_변경_요청.md`(서버 작업).

---

## 0. 배경 / 왜 두 방식이 있나
- **Custom Tabs 방식(권장)**: Google 정책(RFC 8252)에 부합. WebView OAuth 차단 회피 + 자격증명 미노출 + 토큰 URL 비노출. **단, 서버가 `/login/app` + `/auth/exchange`를 구현해야 동작.**
- **WebView 방식(임시/현재)**: 서버의 기존 `/login/swag` 만으로 동작해 **당장 테스트 가능**. 단, Google 정책상 임시용(운영 장기 사용 비권장).

> **현재 상태: WebView 방식** (서버 신규 엔드포인트 미배포 상태에서 테스트하려고 되돌림)

---

## 1. 영향 파일 요약

| 파일 | WebView 방식(현재) | Custom Tabs 방식(권장) |
|---|---|---|
| `app/src/main/java/kr/co/fixlog/activity/GoogleLoginActivity.kt` | WebView로 `/login/swag` 로드 + 콜백 URL 가로채 토큰 파싱 | Custom Tab으로 `/login/app` 오픈 + 딥링크 code 수신 → 교환 |
| `app/src/main/AndroidManifest.xml` | `GoogleLoginActivity` 기본(LAUNCHER만) | `launchMode="singleTask"` + 딥링크 intent-filter 추가 |
| `app/src/main/java/kr/co/fixlog/data/remote/AuthApi.kt` | (미사용) | `exchange(code)` 사용 — **현재도 파일에 유지됨(삭제 불필요)** |

> `AuthApi.exchange(code)`(POST `/auth/exchange`)는 전환을 쉽게 하려고 **WebView 방식에서도 그대로 남겨둔다**(미사용 경고만).

## 2. Custom Tabs로 전환하는 방법 (권장 방식으로 복귀)

> 전제: 서버가 `서버_로그인_변경_요청.md`의 `/login/app` + `/auth/exchange` + 딥링크 리다이렉트를 구현/배포한 상태.

### 2-1. `AndroidManifest.xml` — `GoogleLoginActivity` 를 아래로 교체
```xml
<activity
    android:name=".activity.GoogleLoginActivity"
    android:launchMode="singleTask"
    android:exported="true">
    <intent-filter>
        <action android:name="android.intent.action.MAIN" />
        <category android:name="android.intent.category.LAUNCHER" />
    </intent-filter>

    <!-- OAuth 콜백 딥링크(서버 → 앱). 서버 redirect_uri 화이트리스트와 정확히 일치. -->
    <intent-filter>
        <action android:name="android.intent.action.VIEW" />
        <category android:name="android.intent.category.DEFAULT" />
        <category android:name="android.intent.category.BROWSABLE" />
        <data android:scheme="kr.co.fixlog" android:host="oauth2callback" />
    </intent-filter>
</activity>
```

### 2-2. `GoogleLoginActivity.kt` — 전체를 아래로 교체
```kotlin
package kr.co.fixlog.activity

import android.content.ActivityNotFoundException
import android.content.Intent
import android.net.Uri
import android.os.Bundle
import android.util.Log
import android.widget.Toast
import androidx.activity.enableEdgeToEdge
import androidx.appcompat.app.AppCompatActivity
import androidx.browser.customtabs.CustomTabsIntent
import androidx.core.view.ViewCompat
import androidx.core.view.WindowInsetsCompat
import androidx.lifecycle.lifecycleScope
import kotlinx.coroutines.launch
import kr.co.fixlog.R
import kr.co.fixlog.data.remote.ApiClient
import kr.co.fixlog.data.remote.AuthApi
import kr.co.fixlog.databinding.ActivityGoogleLoginBinding
import kr.co.fixlog.util.SessionManager
import kr.co.fixlog.util.TokenManager
import java.util.UUID

/**
 * Google 권장 방식(RFC 8252): Custom Tabs + 백엔드 브로커드 + 1회용 code 교환.
 * 상세: docs/OAUTH_CUSTOM_TABS_전환.md
 */
class GoogleLoginActivity : AppCompatActivity() {
    private lateinit var binding: ActivityGoogleLoginBinding

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)
        enableEdgeToEdge()
        binding = ActivityGoogleLoginBinding.inflate(layoutInflater)
        setContentView(binding.root)
        ViewCompat.setOnApplyWindowInsetsListener(findViewById(R.id.main)) { v, insets ->
            val b = insets.getInsets(WindowInsetsCompat.Type.systemBars())
            v.setPadding(b.left, b.top, b.right, b.bottom); insets
        }
        SessionManager.reset()

        if (handleAuthCallback(intent)) return
        if (SKIP_LOGIN) { goToMain(); return }
        if (DEV_ACCESS_TOKEN.isNotBlank()) {
            TokenManager.saveTokens(this, DEV_ACCESS_TOKEN, DEV_REFRESH_TOKEN.ifBlank { null }); goToMain(); return
        }
        if (TokenManager.isLoggedIn(this)) { goToMain(); return }

        binding.btnLogin.setOnClickListener { startLogin() }
    }

    override fun onNewIntent(intent: Intent) {
        super.onNewIntent(intent); setIntent(intent); handleAuthCallback(intent)
    }

    private fun startLogin() {
        val state = UUID.randomUUID().toString()
        saveState(state)
        val url = Uri.parse("${ApiClient.BASE_URL}/login/app").buildUpon()
            .appendQueryParameter("redirect_uri", REDIRECT_URI)
            .appendQueryParameter("state", state)
            .build()
        try {
            CustomTabsIntent.Builder().setShowTitle(true).build().launchUrl(this, url)
        } catch (e: ActivityNotFoundException) {
            try { startActivity(Intent(Intent.ACTION_VIEW, url)) }
            catch (e2: ActivityNotFoundException) { toast("로그인을 진행할 브라우저가 없습니다") }
        }
    }

    private fun handleAuthCallback(intent: Intent?): Boolean {
        val uri = intent?.data ?: return false
        if (uri.scheme != CALLBACK_SCHEME || uri.host != CALLBACK_HOST) return false
        val returnedState = uri.getQueryParameter("state")
        val savedState = consumeState()
        if (savedState == null || returnedState != savedState) { toast("로그인 검증에 실패했습니다. 다시 시도해 주세요"); return true }
        val error = uri.getQueryParameter("error")
        if (!error.isNullOrBlank()) { toast("로그인 실패: $error"); return true }
        val code = uri.getQueryParameter("code")
        if (code.isNullOrBlank()) { toast("로그인 실패: 인증 코드를 받지 못했습니다"); return true }
        exchangeCode(code); return true
    }

    private fun exchangeCode(code: String) {
        lifecycleScope.launch {
            runCatching { AuthApi.exchange(code) }
                .onSuccess { t -> TokenManager.saveTokens(this@GoogleLoginActivity, t.accessToken, t.refreshToken); goToMain() }
                .onFailure { e -> Log.w(TAG, "code 교환 실패", e); toast("로그인에 실패했습니다. 다시 시도해 주세요") }
        }
    }

    private fun goToMain() {
        startActivity(Intent(this, DocumentsActivity::class.java).apply {
            flags = Intent.FLAG_ACTIVITY_CLEAR_TOP or Intent.FLAG_ACTIVITY_SINGLE_TOP
        }); finish()
    }

    private fun saveState(s: String) = getSharedPreferences(PREF_OAUTH, MODE_PRIVATE).edit().putString(KEY_STATE, s).apply()
    private fun consumeState(): String? {
        val p = getSharedPreferences(PREF_OAUTH, MODE_PRIVATE)
        return p.getString(KEY_STATE, null).also { p.edit().remove(KEY_STATE).apply() }
    }
    private fun toast(m: String) = Toast.makeText(this, m, Toast.LENGTH_SHORT).show()

    companion object {
        private const val TAG = "GoogleLogin"
        private const val SKIP_LOGIN = false
        private const val DEV_ACCESS_TOKEN = ""
        private const val DEV_REFRESH_TOKEN = ""
        private const val CALLBACK_SCHEME = "kr.co.fixlog"
        private const val CALLBACK_HOST = "oauth2callback"
        private const val REDIRECT_URI = "$CALLBACK_SCHEME://$CALLBACK_HOST"
        private const val PREF_OAUTH = "fixlog_oauth"
        private const val KEY_STATE = "oauth_state"
    }
}
```

### 2-3. `AuthApi.kt`
- `exchange(code)` 가 이미 존재하면 그대로 사용. 없으면 아래를 추가:
```kotlin
suspend fun exchange(code: String): TokenResponse = withContext(Dispatchers.IO) {
    val payload = JSONObject().put("code", code).toString()
    val request = Request.Builder().url("${ApiClient.BASE_URL}/auth/exchange")
        .post(payload.toRequestBody(JSON)).build()
    val response = ApiClient.httpClient.newCall(request).execute()
    val body = response.use { it.body?.string() } ?: throw IOException("Empty response body")
    val obj = JSONObject(body)
    val respCode = obj.optString("code")
    if (respCode.isNotEmpty() && respCode != "SUCCESS")
        throw IOException("API error: code=$respCode, message=${obj.optString("message")}")
    val result = obj.optJSONObject("result") ?: obj
    val access = result.optString("accessToken").ifBlank { result.optString("token") }
    if (access.isBlank()) throw IOException("exchange succeeded but no accessToken")
    TokenResponse(accessToken = access, refreshToken = result.optString("refreshToken").ifBlank { null })
}
```

### 2-4. 검증
실기기에서 로그인 → 시스템 브라우저 Google 로그인 → 앱 복귀 → `POST /auth/exchange` 성공 → 문서 화면.

## 3. WebView로 되돌리는 방법 (현재 적용 상태)

### 3-1. `AndroidManifest.xml`
`GoogleLoginActivity` 에서 `android:launchMode="singleTask"` 와 **딥링크 intent-filter(VIEW/BROWSABLE, scheme=kr.co.fixlog host=oauth2callback)** 를 제거하고 LAUNCHER intent-filter만 남긴다.

### 3-2. `GoogleLoginActivity.kt`
WebView 버전으로 교체(현재 저장소 상태). 핵심:
- `btn_login` → `launchGoogleLogin()` : WebView로 `"$AUTH_BASE_URL/login/swag"` 로드
- `SwagCallbackClient.shouldOverrideUrlLoading` 에서 `"$AUTH_BASE_URL/login/swag/callback"` 을 가로채 `accessToken`/`refreshToken` 파싱 → `TokenManager.saveTokens` → `goToMain()`
- 상수: `AUTH_BASE_URL = "https://fixlog.art/fixlog"`, `SWAG_CALLBACK_PATH = "/login/swag/callback"`

### 3-3. `AuthApi.exchange`
그대로 두어도 무방(미사용). 완전 정리를 원하면 삭제 가능.

## 4. 공통 / 변하지 않는 것
- `POST /auth/token/refresh`(재발급), `GET /auth/token`(현재 사용자) — **두 방식 모두 동일**.
- `TokenManager` 저장, `AuthInterceptor`(Bearer + X-Workspace-Id), `TokenAuthenticator`(401 재발급) — 동일.
- `ApiClient.BASE_URL = "https://fixlog.art/fixlog"`.
- 로그인 후 진입 화면: `DocumentsActivity`.

## 5. 테스트용 로그인 건너뛰기 (두 방식 공통)
- `GoogleLoginActivity` 의 `SKIP_LOGIN = true` → 인증 없이 진입(단, 보호 API는 401 → 로그인으로 튕김).
- `DEV_ACCESS_TOKEN`/`DEV_REFRESH_TOKEN` 에 실제 토큰을 넣으면 로그인 스킵 + 서버 데이터 정상.
  - 토큰 발급: 브라우저로 `https://fixlog.art/fixlog/login/swag` 로그인 → 콜백 URL의 토큰 복사.
- **운영 배포 전 반드시 `SKIP_LOGIN=false`, 두 토큰 상수 `""` 로 복원.**
