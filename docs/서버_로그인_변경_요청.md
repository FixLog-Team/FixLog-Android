# 서버 로그인 변경 요청 (Android Custom Tabs 전환)

> 대상: FixLog 백엔드 담당자 / AI 에이전트
> 요지: 안드로이드 로그인을 **WebView → Custom Tabs(외부 브라우저)** 로 바꾼다. 서버는 **엔드포인트 2개 추가**만 하면 되고,
> **refresh · 현재 사용자 조회 · JWT 발급 · Google OAuth 설정은 그대로**다.

---

## 1. 무엇이 문제였나
- 기존 안드로이드는 **앱 내 WebView로 Google 로그인**을 띄우고, 브라우저 UA로 위장해 우회했다.
- 문제: ① Google 정책 위반(`disallowed_useragent`로 WebView OAuth 차단) ② 보안 취약(앱이 자격증명 접근 가능)
  ③ 콜백 URL에 **accessToken/refreshToken이 그대로 노출**(브라우저 히스토리/Referer 유출 위험).

## 2. AS-IS (기존)
```
앱 WebView → GET /login/swag → (Google 로그인) →
서버가 302: /login/swag/callback?accessToken=...&refreshToken=...  ← 토큰을 URL로 직접 전달
앱이 WebView에서 이 URL을 가로채 토큰 파싱
```

## 3. TO-BE (변경)
```
앱 Custom Tab → GET /login/app?redirect_uri=kr.co.fixlog://oauth2callback&state={nonce}
→ (시스템 브라우저에서 Google 로그인) →
서버가 302: kr.co.fixlog://oauth2callback?code={app_code}&state={nonce}  ← 1회용 code만 전달
→ 앱: POST /auth/exchange { code } → { accessToken, refreshToken }        ← 토큰은 여기서 교환
```
핵심: **딥링크에는 토큰 대신 1회용 code만.** 토큰은 별도 POST로 교환.

---

## 4. 서버가 변경/추가할 것

### 4.1 [추가] 모바일 로그인 시작 — `GET /login/app`
- 파라미터: `redirect_uri`, `state`
- 동작: `redirect_uri`·`state`를 세션(또는 서명 저장소)에 보관 후 Google 인가로 302.
- **필수 검증**: `redirect_uri` 화이트리스트 = `kr.co.fixlog://oauth2callback` (그 외 400).
- 기존 `/login/swag`의 OAuth 로직 재사용 가능. 차이는 "성공 후 4.2로 리다이렉트".

### 4.2 [변경] 성공 콜백 — 토큰 URL 노출 → 1회용 code 딥링크
- Google 콜백 처리(서버가 code↔token 교환, PKCE는 서버 수행) 후:
  - **1회용 `app_code` 발급**: 안전 난수(≥128bit), **TTL 60초**, **1회 사용**, `state`/userId에 바인딩.
  - 서버에 `app_code → {accessToken, refreshToken}` 임시 저장(Redis 등).
  - 302 → `kr.co.fixlog://oauth2callback?code={app_code}&state={state}`
  - 실패 시 → `kr.co.fixlog://oauth2callback?error={code}&state={state}`
- ⚠️ **딥링크에 accessToken/refreshToken 금지.** `app_code`만.

### 4.3 [추가] code 교환 — `POST /auth/exchange`
- 요청: `{ "code": "<app_code>" }`
- 동작: `app_code` 존재·미만료·미사용 확인 → **즉시 소비** → 토큰 반환.
- 응답(공통 래퍼):
  ```json
  { "code": "SUCCESS", "message": "", "result": { "accessToken": "<JWT>", "refreshToken": "<JWT>" } }
  ```
- 실패: `code != "SUCCESS"` + HTTP 400/401.

### 4.4 보안 체크리스트
- [ ] `redirect_uri` 정확히 `kr.co.fixlog://oauth2callback`만 허용
- [ ] `app_code` 단기 TTL·1회용·바인딩·안전 난수
- [ ] 딥링크에 토큰 미포함(코드만)
- [ ] `state` 왕복 보존(앱이 CSRF 검증)
- [ ] `app_code`·토큰 로그 미기록

---

## 5. 그대로 두는 것 (변경 없음)
- `POST /auth/token/refresh` — 재발급. 동일.
- `GET /auth/token` — 현재 로그인 사용자 조회. 동일.
- JWT 발급 로직 / 토큰 TTL(access 1h, refresh 14d) / Google Cloud OAuth 설정(Authorized redirect URI = 서버 콜백 URL 그대로, 앱 스킴 등록 불필요).
- 기존 `/login/swag(/callback)` — 웹 프론트가 계속 사용하면 유지.

---

## 6. 완료 기준
1. `GET /login/app` 로 시작 → 시스템 브라우저 Google 로그인 → `kr.co.fixlog://oauth2callback?code=&state=` 로 복귀.
2. `POST /auth/exchange { code }` 가 access/refresh 반환.
3. 반환 토큰으로 `GET /auth/token`, `POST /auth/token/refresh` 정상 동작(기존 그대로).
